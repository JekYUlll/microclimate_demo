# v1 实验后续指示：分支决策树

## 核心诊断结论（基于现有 CHANGELOG）

在进入分支指示之前，需要明确当前失败的根本原因，因为它决定了所有后续分支的优先级。

**已确认的失败模式：** 验证窗口到最终测试窗口的 regime 迁移失败（validation-to-final transfer failure），而非 teacher 缺失或监督头不足。证据如下：

- Teacher 在 n=15 中赢得 10/11（dense12 valguard）或 10/11（riskcenter extension early stop），始终稳定。
- Deployable 在 n=5 上可以通过（riskcenter: 4/5），但在 extension seeds 46–55 上系统性失败（riskcenter extension: 7/11 early stop；riskband: 1/4）。
- 关键信号：seed52/53 的验证中心为正（mean +0.007865 / +0.006004），q25 也满足 risk-band 条件，但最终测试均为负（-0.001305 / -0.005976）。这证明验证分布本身无法预测最终迁移方向。
- 所有额外监督头（teacher-rate、contextual-duty、recurrent、sequence-mask GRU）均已关闭，未能改善迁移。

**结论：** 当前瓶颈是 **start-regime 结构性迁移风险**，不是策略类型或监督信号的问题。继续添加新的策略头是低价值路径。

## 主分支：Start-Regime 迁移风险建模

### Branch A：Per-Start 迁移预测器（推荐优先尝试）

**动机：** Start-level audit 显示失败是 start/regime 结构化的（seed44 全部 0/4 starts 失败；seed52/53 的 start-level wins 仅 2/8）。验证窗口的聚合统计（mean/median/q25）无法捕捉 start-level 的异质性。需要在 start 粒度上建模迁移风险。

**具体指示：**

1. 构建 per-start 特征矩阵。对每个验证 start，提取以下特征：
   - 该 start 的验证 margin（event-threshold deployable vs. static anchor）
   - 该 start 的 SOC 初始值、事件密度（前 N 步内 z_t=1 的比例）、teacher 在该 start 的 margin
   - 该 start 的 action mask（选中的 event-threshold action id）
   
2. 用已有的 9 条 selected deployable rows（来自 `audit_transfer_risk_selector.py` 的数据）以及对应的 per-start 最终结果，训练一个轻量级迁移预测器（logistic regression 或 gradient boosting，特征维度低，避免过拟合）。目标变量：该 start 在最终测试中是否为正 margin。

3. 在部署选择时，用预测器对候选 event-threshold 行的所有验证 starts 打分，选择预测正 margin starts 比例最高的行，而非依赖聚合统计。

**如果成功（n=5 gate 通过，且 extension seeds 46–51 重跑后 ≥8/10 wins）：**
→ 进入 Branch A-ext：用 seeds 46–55 完整跑 n=10 extension，目标 combined n=15 达到 12/15。

**如果失败（n=5 gate 不通过，或 extension 仍 ≤7/11）：**
→ 进入 Branch B（见下）。不要继续在迁移预测器上叠加复杂度。

---

### Branch B：Start-Conditioned 静态回退策略（保守路径）

**动机：** 如果迁移预测器无法可靠工作，说明当前 event-threshold 策略在某些 start regime 下本质上不优于静态基线。此时应接受这一事实，转而构建一个 **start-conditioned 部署决策**：对于预测为"不支持"的 start，直接回退到 validation-selected static，而非强行部署 event-threshold。

**具体指示：**

1. 在 `run_protocol_gate.py` 中，对每个最终测试 start，独立运行 event-threshold deployable 和 static anchor，记录 per-start 结果。

2. 在验证阶段，对每个 start 独立判断 event-threshold 是否优于 static（而非聚合判断）。只在验证中该 start 为正 margin 的 starts 上部署 event-threshold；其余 starts 回退到 static。

3. 这实际上是一个 **start-level oracle 混合策略**。其上界是 start-level oracle（每个 start 都选最优），下界是纯静态。目标是验证：start-level 混合策略的 n=15 win rate 是否能达到 12/15。

**如果成功（n=15 ≥12/15）：**
→ 这是一个有效的 **条件部署结论**，可以作为 Paper 2 的核心发现之一：event-threshold 策略在特定 start regime 下有价值，但需要 start-level 验证支持。注意：这不是一个无条件的强 claim，需要在论文中诚实描述为"条件有效"。

**如果失败（n=15 仍 <12/15，即使 start-level 混合也不够）：**
→ 进入 Branch C（见下）。

---

### Branch C：重新评估 Claim 强度（降级路径）

**动机：** 如果 Branch A 和 Branch B 均失败，说明当前 v1 系统在 n=15 强 gate 下无法支持无条件的"动态策略优于静态基线"的 claim。此时应停止追求 12/15 gate，转而重新定义可支持的 claim。

**具体指示：**

1. **重新定义 claim 为条件性结论：** "在 B=1.20 能量账户场景下，当验证 regime 支持正中心迁移时（约 4/5 seeds），forecast-aware event-threshold 策略优于 validation-selected static；在不支持的 regime 下（约 1/5 seeds），静态回退是最优选择。" 这与 Paper 1 的三层论证结构完全一致，可以作为 Paper 2 的 §7.1 诚实结论。

2. **停止所有新的监督头实验。** 不要再尝试 teacher-rate、contextual-duty、recurrent 等变体。这些路径已经系统性关闭（见 CHANGELOG §3）。

3. **将 v1 当前最佳结果（riskcenter n=5: 4/5，conservative margin mean +0.011105）作为 Paper 2 的 preliminary evidence**，配合 start-level audit（15/16 selected starts win）作为机制证据。

4. **将 Paper 2 的 §7.4 Limitations 中明确写入：** n=15 强 gate 未达到；失败模式是 start-regime 结构性迁移风险；未来工作需要 start-conditioned 部署协议或更长的验证序列。

## 次要分支：诊断实验（不阻塞主分支，可并行）

### Diag-1：Spearman 相关性诊断（已在 unresolved 中标记）

**目的：** 区分迁移失败是"协议结构性"（验证窗口和最终窗口的 regime 系统性不同）还是"策略结构性"（策略本身在某些 regime 下不稳定）。

**指示：** 对 seeds 41–55 中所有已完成的 seeds，计算 per-seed 的 Spearman 相关系数：(validation_loss_dynamic, final_loss_dynamic) vs. (validation_loss_static, final_loss_static)。如果静态基线的 Spearman 相关也低，说明是协议结构性问题；如果静态相关高而动态相关低，说明是策略结构性问题。

**如果是协议结构性：** 考虑延长验证序列（从 12 starts 增加到 24 starts），或使用滑动窗口验证覆盖更多 regime。

**如果是策略结构性：** 说明 event-threshold 策略在某些 regime 下本质不稳定，Branch B 的 start-conditioned 回退是正确方向。

---

### Diag-2：Seed44 Regime 分析

**目的：** Seed44 是系统性失败的代表（0/4 starts，所有方法均失败）。理解其失败原因有助于判断是否存在可修复的 regime 覆盖问题。

**指示：** 对 seed44 的最终测试窗口，提取以下统计：事件密度（z_t=1 比例）、SOC 初始分布、teacher 在该窗口的 action 分布。与 seed41（强正 margin）对比。如果 seed44 的事件密度极低（接近 0），说明该 seed 的最终窗口几乎没有事件，event-threshold 策略无法发挥作用，这是一个 regime 边界条件，不是策略失败。

**如果是 regime 边界：** 在 Paper 2 中将 seed44 类型的 regime 明确排除在 claim 范围之外，并在 §3.1 中定义 claim 的适用条件（最低事件密度阈值）。

**如果不是 regime 边界（事件密度正常但策略仍失败）：** 说明策略在该 regime 下存在系统性偏差，需要进一步诊断（见 Branch B）。

## 执行优先级总结

当前状态下，推荐的执行顺序如下：

首先，并行运行 Diag-1 和 Diag-2，因为它们是零成本诊断，结果直接影响 Branch A/B 的设计决策。在诊断结果出来之前，不要启动新的大规模训练运行。

其次，根据 Diag-1 结果决定 Branch A 的特征设计：如果是协议结构性失败，优先在特征中加入 regime 覆盖统计；如果是策略结构性失败，优先在特征中加入 action mask 稳定性指标。

第三，尝试 Branch A（per-start 迁移预测器）。如果 n=5 gate 通过且 extension 初步结果（seeds 46–49）显示 ≥3/4 wins，继续扩展到 n=15；否则立即切换到 Branch B，不要在 Branch A 上继续迭代。

第四，如果 Branch A 和 Branch B 均失败，执行 Branch C（降级 claim），停止所有新实验，将现有最佳结果整理为 Paper 2 的 preliminary evidence。

**明确的停止条件：** 如果在 Branch A 的 extension 阶段（seeds 46–51）出现 ≤5/6 wins，立即停止，不要等到 seeds 52–55。数学上，5/6 extension wins 加上原始 4/5 wins 最多达到 9/11，无法支持 12/15 gate。
