## 二、当前状态精确摘要

### 2.1 场景状态（锁定）

**v6/event-transport 场景已通过 static/teacher 校准门控（3/3 seeds，teacher wins 3/3，mean teacher margin +0.098–+0.110）。**

关键场景特性：
- 静态策略不再持续激活 laser：所有 3 个种子的 static laser duty = 0
- 教师策略使用 15–20 个唯一 mask，fc4 duty ≈ 0.80，SPC duty ≈ 0.60，laser duty ≈ 0
- 动态价值来源：SPC/fc4/context 的时序互补，而非 laser burst
- 教师 task-error margin 在所有种子均为正（+0.129 至 +0.238）

**这个场景本身不是瓶颈。** 瓶颈是 deployable 学生接口。

### 2.2 Switching-Pattern Audit 关键发现（锁定）

`switching_audit_v6_transport_20260604` 揭示了教师与学生之间的根本行为差异：

| 指标 | Static | Deployable students | MPC Teacher |
|---|---|---|---|
| Always-on sensors | 3–4 | 3.33（event-threshold）/ 2.67（option-planner） | 仅 met_station_core |
| Switch rate | 0% | 7–24% | 70.45% |
| 3+ simultaneous switches | 0% | <1% | 15.97% |

**结论：** 当前所有 deployable 学生（包括 option-planner）都将教师的频繁多传感器时序混合压缩为"固定核心 + 间歇辅助通道"模式。这是**学生接口限制**，不是场景设计失败。

### 2.3 Objective Transfer Audit 关键发现（锁定）

`objective_transfer_audit_v6_20260604` 确认：
- 教师在 3/3 seeds、12/12 final windows 均为正
- 教师 objective margin mean = +0.110656
- 教师 oracle-loss margin = +0.043868，task-error margin = +0.222628
- task-error 贡献约 60.4% 的 objective lift
- 教师平均功耗低于 static（-0.055186）

**场景不是瓶颈，deployable 因果转移/选择是瓶颈。**

### 2.4 当前最佳 Deployable 证据（保留）

**v1 riskcenter n=5（B=1.20，旧场景）：4/5 wins，conservative margin mean +0.011105，15/16 selected starts win。**

这是 Paper 2 §7.1 的初步证据，不受 v6 实验影响。

### 2.5 Option-Planner Seed44 Win（保留为诊断信号）

在 v6/event-transport option-planner posguard smoke 中，seed44 产生了真实的 final win（+0.007593）。这是 v6 场景下唯一的 deployable final win，表明 option-planner 接口在特定制度条件下有效。

## 三、根因诊断（最终版）

综合 CHANGELOG §7 的全部实验，根因诊断如下：

**根因 1：学生接口无法压缩教师的多传感器时序混合行为。**

序列 mask 拟合（exact match ≥ 0.996）、recurrent cost-DAgger（ranking accuracy 提升至 0.47–0.59）、macro-option snippet（teacher 标签片段）均失败。这说明失败不是标签质量或数据量问题，而是**学生在 closed-loop 执行中无法维持教师的时序结构**。

**根因 2：验证窗口对 final 窗口的预测力极弱（Spearman 0.204/0.280），且这一弱预测力在 v6 场景下同样成立。**

Runtime-risk guard（paired replay）：验证正但 final 负。Cost-KNN：验证阶段已失败。Macro-option：验证阶段已失败。这说明问题不仅是 final transfer，而是**学生在验证窗口本身就无法稳定地超越 static**。

**根因 3：当前 deployable 学生的因果输入不包含教师改善/遗憾窗口的直接信号。**

`objective_transfer_audit` 发现：当前 artifact 不保存 learned-event 概率列或 TeacherDataset 特征名，无法直接审计 learned-event 校准与教师改善窗口的对齐情况。`auditable_deployable_context_persistence` 修复了这一 artifact 缺口（CHANGELOG 最后一条），但尚未用于新实验。

## 四、下一步行动计划（修订版，替换 Turn 87 草稿）

### 4.1 立即可执行：Teacher-Improvement Window Alignment Audit（零新训练）

**目的：** 利用新增的 `truth_with_learned_event_forecast.csv` 和 TeacherDataset feature names，直接审计 learned-event 概率与教师改善窗口的对齐情况。

**具体步骤：**
1. 从 v6/event-transport 的已完成 run roots 中读取 `truth_with_learned_event_forecast.csv`
2. 对每个 final window，计算：
   - 教师改善窗口（teacher objective < static objective 的时间步）
   - Learned-event 概率均值（$\bar{\hat{z}}_{t:t+h}$）在教师改善窗口 vs 非改善窗口的分布差异
3. 若 learned-event 概率在教师改善窗口显著更高（Mann-Whitney U p < 0.05），则 learned-event 信号是有效的因果特征，可用于 option-planner 的 entry gate
4. 若无显著差异，则 learned-event 信号本身不足以区分教师改善窗口，需要引入额外的 transport-aware 特征（SPC/fc4 互补性指标）

**成本：** 零新训练，仅需脚本分析。

**决策门：**
- 若 learned-event 对齐显著 → 进入 Branch F（option-planner with teacher-improvement entry gate）
- 若不显著 → 进入 Branch G（transport-aware feature redesign）或 Branch C（声明降级）

### 4.2 Branch F：Option-Planner with Teacher-Improvement Entry Gate

**前提：** Teacher-improvement window alignment audit 显示 learned-event 信号有效。

**核心思路：** 将 option-planner 的 entry gate 从"事件概率超过阈值"改为"预测的教师改善概率超过阈值"。具体地，用 train-split 数据拟合一个轻量级分类器，输入为 $(s_t, \hat{z}_{t:t+h}, \text{SOC}_t, \text{freshness}_t)$，输出为"教师在此时间步是否改善 static"的概率。

**实施步骤：**
1. 从 train-split teacher rollouts 中提取 $(s_t, \hat{z}_{t:t+h}, \text{SOC}_t, \text{freshness}_t, \mathbb{1}[\text{teacher improves static at } t])$ 数据集
2. 训练轻量级分类器（logistic regression 或 gradient boosting，深度 ≤ 3）
3. 将分类器输出作为 option-planner 的 entry gate：仅在预测改善概率 ≥ θ 时激活 option-planner
4. 在 seeds 41/42/44 上评估；成功标准：≥ 2/3 wins（小门控）

**成本：** 零新 PPO 训练；仅需分类器拟合（< 1 分钟）和 3 个种子的 final replay。

**成功标准：** seeds 41/42/44 gate ≥ 2/3 wins → 扩展至 n=5（seeds 41–45）→ n=5 gate ≥ 4/5 → 扩展至 n=15

**失败处理：** 若 seeds 41/42/44 gate < 2/3，转 Branch G 或 Branch C。

### 4.3 Branch G：Transport-Aware Feature Redesign（需要重新设计 deployable 接口）

**前提：** Teacher-improvement window alignment audit 显示 learned-event 信号不足，或 Branch F 失败。

**核心思路：** 当前 deployable 学生的失败根因是无法压缩教师的 SPC/fc4/context 时序互补行为。这需要一个**显式建模传感器互补性**的 deployable 接口，而非仅仅依赖事件概率或 duty rate。

**具体方向：**
- 引入 transport-aware 特征：SPC 与 fc4 的互补性指标（如 SPC 粒径方差 × fc4 通量方差的乘积）
- 将 option-planner 的 option set 从"event-threshold 触发的 mask 切换"改为"SPC/fc4/context 互补性触发的 mask 切换"
- 这需要重新设计 `ForecastAwareOptionPlannerPolicy` 的 option 定义和 entry gate

**成本：** 需要代码修改（约 1–2 天）+ seeds 41/42/44 smoke（约 2–4 小时）。

**决策门：** 若 seeds 41/42/44 gate ≥ 2/3 → 扩展；否则转 Branch C。

### 4.4 Branch C（保持不变）：声明降级

若 Branch F 和 Branch G 均失败，或作者判断继续实验的边际收益不足：

**Paper 2 §7.1 证据：** v1 riskcenter n=5（B=1.20，4/5 wins，conservative margin mean +0.011105，15/16 selected starts win）

**Paper 2 §7.4 Limitations 内容：**
- Spearman 0.204/0.280：验证窗口对 final 窗口预测力极弱
- 学生接口无法压缩教师的多传感器时序混合（sequence-mask exact match ≥ 0.996 仍失败）
- v6 场景下 14 种 deployable 接口均未通过 seeds 41/42/44 gate（除 option-planner seed44 单点 win）
- per-start oracle static fallback 上界（13/13，+0.008638）表明问题可解，但需要更强的因果接口

**Paper 2 §8 Future Work：** 引用 Branch F/G 的方向，以及 Jiang 等人（2026）的解耦安全监督框架

## 六、已关闭路径的文献锚点更新

以下文献锚点的适用范围在本轮实验后需要更新：

**CAPS（Chemingui et al., 2025）：** 约束过滤机制（$Q^c_t + c_{<t} \leq \kappa$）在 v6 场景下不适用，因为 v6 的 deployable 失败不是约束违反导致的（教师功耗低于 static，约束非绑定）。CAPS 的**策略集合设计思路**（覆盖不同奖励-代价权衡的策略集合）仍然有参考价值，但需要适配为"覆盖不同传感器互补性模式的 option 集合"。

**TREBI（Lin et al., 2023）：** Theorem 4.1 的轨迹加权公式在 v6 场景下的适用性存疑，因为 v6 的 deployable 失败发生在验证阶段（而非 final transfer），说明问题不是轨迹分布偏移，而是学生接口本身的表达能力不足。TREBI 的**轨迹优化视角**（将策略优化转化为轨迹分布优化）仍然有理论价值，可用于 Paper 2 §4 的形式化。

**MPC-PPO（Yu et al., 2025）：** 动态替换机制在 v6 场景下的适用性需要重新评估。v6 的教师已经稳定（3/3 seeds，mean margin +0.110），问题不是教师质量，而是学生压缩接口。MPC-PPO 的**预训练阶段高比例注入**思路仍然有参考价值，但需要与 Branch F/G 的新接口结合。

**解耦安全监督（Jiang et al., 2026）：** 独立安全价值网络 $G(s, a | \theta^G)$ 的梯度修正机制在 v6 场景下的适用性存疑，因为 v6 的约束（B=1.36）相对宽松，教师功耗低于 static，约束不是主要瓶颈。该框架更适合作为 Paper 2 §8 Future Work 的引用，而非当前实验的直接工具。

**Fernández-Bes et al.（2015）Theorem 1：** 对 Paper 1 的理论锚点不受影响。

## 七、对 Paper 2 写作的影响（最终版）

### 7.1 §4（Forecast-Aware CMDP Framework）

v6 场景的 static/teacher 校准结果（teacher wins 3/3，mean margin +0.110，task-error margin +0.223）提供了强有力的**动态价值存在性证明**，可作为 Paper 2 §4 的实验动机。引用 Kongarana 等人（2026）BAFS-CMDP 作为形式化基础。

### 7.2 §5（MPC-Teacher Distillation）

v6 场景的教师行为分析（15–20 unique masks，fc4/SPC/context 时序互补，switch rate 70.45%）提供了**教师行为的定性描述**，可作为 Paper 2 §5 的 teacher characterisation。引用 Yu 等人（2025）MPC-PPO 作为教师-学生集成的先例。

### 7.3 §7.1（Results）

- 若 Branch F 成功：定位为"基于教师改善窗口预测的 option-planner 在事件感知传感器调度中的首次应用"
- 若 Branch G 成功：定位为"transport-aware 特征驱动的 deployable 接口"
- 若 Branch C：使用 riskcenter n=5（4/5）作为初步证据，诚实报告 v6 场景下 14 种接口的系统性失败

### 7.4 §7.4（Limitations）

无论哪条路径成功，均应报告：
- 学生接口无法压缩教师的多传感器时序混合（sequence-mask exact match ≥ 0.996 仍失败）
- 验证窗口对 final 窗口预测力极弱（Spearman 0.204/0.280）
- v6 场景下 14 种 deployable 接口的系统性失败（除 option-planner seed44 单点 win）
- 引用 Jiang 等人（2026）解耦安全监督框架作为未来方向
